  <files>src/useUrlFetch.ts</files>
  <action>
    Create the useUrlFetch hook that orchestrates the full fetch pipeline.

    **Exported types:**
    ```typescript
    interface ExtractionStep {
      id: string;
      label: string;
      status: 'pending' | 'active' | 'done' | 'error';
      detail?: string;
    }

    interface ExtractionState {
      status: 'idle' | 'extracting' | 'done' | 'error';
      steps: ExtractionStep[];
      domain: string;
      error?: { headline: string; detail: string };
    }

    interface FetchResult {
      html: string;
      css: string[];  // Array of CSS content strings
      url: string;
    }
    ```

    **Hook signature:** `useUrlFetch() -> { state: ExtractionState, startExtraction: (url: string) => void, cancel: () => void, reset: () => void, result: FetchResult | null }`

    **Implementation details:**
    1. Uses `useShell()` to get shell access
    2. `cancelledRef = useRef(false)` for cancel support (per research Pattern 3)
    3. `startExtraction(url)`:
       - Sets status to 'extracting', resets cancelledRef
       - Extracts domain from URL for display: `new URL(url).hostname`
       - Step 1: "Fetching page..." (active) -- calls `fetchHtml(shell, url)`
         - After: checks `cancelledRef`, checks `detectBotProtection(html, headers)`
         - If bot detected: set step 1 to error, set state error with bot provider info, return
         - If success: set step 1 to done
       - Step 2: "Loading stylesheets..." (active)
         - Calls `extractStylesheetUrls(html, url)` to get CSS URLs
         - Loops through CSS URLs, fetching each with `fetchCss(shell, cssUrl)`
         - Updates step 2 detail as "Loading stylesheets (2/5)..." with count
         - Checks `cancelledRef` before each fetch
         - Collects CSS content strings (skip failures silently -- some CSS files may 404)
         - After all: set step 2 to done
       - Sets status to 'done', stores FetchResult
    4. `cancel()`: sets cancelledRef.current = true, resets state to idle
    5. `reset()`: resets state to idle, clears result
    6. Error handling: wrap entire flow in try/catch. On error, set the active step to 'error' status, set state.error with headline and detail. Map known errors:
       - "Site took too long to respond" -> headline: "Connection timed out"
       - "Response too large" -> headline: "Page too large to process"
       - Bot detection error -> headline: "Site may be bot-protected", detail includes provider
       - Generic -> headline: "Could not fetch page"
