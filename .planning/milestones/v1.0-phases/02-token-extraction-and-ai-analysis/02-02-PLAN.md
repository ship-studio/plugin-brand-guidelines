  <behavior>
    ## analyzeTokens(shell, colors, fonts, visibleText)
    - Calls shell.exec('claude', ['-p', prompt, '--max-turns', '1', '--output-format', 'text'], { timeout: 120000 })
    - Returns AnalysisResult: { colors: Array<{name, hex}>, fonts: Array<{role, value}>, voiceNotes: string }

    ## buildPrompt(colors, fonts, visibleText)
    - Builds a prompt string containing: color list with hex + varName hints, font list, visible text
    - Instructs Claude to output ONLY JSON matching the schema
    - Truncates total CSS-derived content to ~100KB (AINT-02)
    - Returns the prompt string

    ## parseAnalysisResponse(stdout)
    - Parses JSON from Claude's response
    - Strips markdown fences (```json...```) if present
    - Falls back to finding first { and last } if fence stripping fails
    - Returns AnalysisResult
    - Throws on unparseable response

    ## Test cases (mocked shell):
    - shell.exec is called with 'claude', args array containing '-p' and '--max-turns', timeout 120000
    - Prompt includes color hex values and CSS variable names
    - Prompt includes font names
    - Prompt includes visible text (truncated)
    - Clean JSON response parses correctly
    - JSON wrapped in ```json``` fences parses correctly
    - JSON with leading text ("Here is the analysis:") parses correctly
    - Non-zero exit code throws error
    - Invalid JSON triggers retry (shell.exec called twice)
    - After second failure, throws descriptive error
    - buildPrompt truncates input when total exceeds ~100KB
    - Empty color/font arrays produce valid prompt (edge case)
  </behavior>
  <action>
    Create `src/analyzeTokens.ts`:

    1. **AnalysisResult interface** — `{ colors: Array<{name: string, hex: string}>, fonts: Array<{role: string, value: string}>, voiceNotes: string }`

    2. **buildPrompt(colors: RawColor[], fonts: string[], visibleText: string): string** —
       - Format colors as a list: `#6c5ce7 (--color-primary)` or `#6c5ce7` if no varName
       - Format fonts as comma-separated list
       - Include visible text (already truncated to 10KB by extractVisibleText)
       - Truncate the CSS-derived sections if total prompt would exceed ~100KB
       - Instruction block tells Claude to:
         - Select 5-12 most meaningful colors, assign creative semantic names based on the brand
         - Classify fonts into roles (Heading, Body, Mono, etc.)
         - Generate voice/tone notes as structured bullet points (tone, vocabulary, personality, do's/don'ts)
         - Output ONLY valid JSON matching the schema, no markdown fences, no explanation

    3. **parseAnalysisResponse(stdout: string): AnalysisResult** —
       - Try JSON.parse(stdout.trim()) first
       - If fails, strip markdown fences: regex `/```(?:json)?\s*([\s\S]*?)\s*```/`
       - If still fails, find first `{` and last `}`, try parsing that substring
       - Throw Error('Failed to parse AI response') if all fail

    4. **analyzeTokens(shell, colors, fonts, visibleText): Promise<AnalysisResult>** —
       - Call shell.exec('claude', ['-p', buildPrompt(colors, fonts, visibleText), '--max-turns', '1', '--output-format', 'text'], { timeout: 120000 })
       - Check exit_code !== 0 -> throw Error with stderr
       - Try parseAnalysisResponse(result.stdout)
       - On parse failure: retry once with a stricter prompt (add "You MUST output ONLY valid JSON. No other text.") per CONTEXT.md decision
       - On second failure: throw Error('AI analysis failed: could not parse response')

    Export: `AnalysisResult`, `analyzeTokens`, `buildPrompt` (buildPrompt exported for testing)

    Create `src/analyzeTokens.test.ts` with `// @vitest-environment jsdom` and mockShell pattern from fetchUtils.test.ts.
