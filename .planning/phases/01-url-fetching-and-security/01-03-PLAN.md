    **BrandModal.tsx rewrite:**
    Implement the view state machine per locked decisions from CONTEXT.md.

    1. Add view state type: `type ModalView = 'url-cta' | 'tabs' | 'url-inline' | 'extracting';`
    2. Initialize view based on brand data: `hasBrandData(settings) ? 'tabs' : 'url-cta'`
    3. Call `useUrlFetch()` hook for fetch orchestration
    4. Track `lastUrl` in state for retry pre-fill
    5. View rendering:

    **url-cta view** (empty state, per locked decision):
    - Full modal body takeover -- centered content
    - Headline: "Start from a URL" or similar
    - Subtext: "Enter a website URL to extract brand colors, fonts, and voice"
    - Render `<UrlInputView onExtract={handleExtract} />`
    - "Or set up manually" link below -- clicking sets view to 'tabs'
    - Tabs are NOT rendered in this view
    - No footer in this view

    **tabs view** (existing behavior, mostly preserved):
    - Render tabs + tab content + footer exactly as current BrandModal does
    - When `hasBrandData(settings)` is true, pass `headerActions` to Modal containing a small icon button (globe/link icon, ~16x16px SVG)
    - Clicking the icon button sets view to 'url-inline'

    **url-inline view** (header bar input, per locked decision):
    - Tabs remain visible but the URL input bar appears between header and tabs
    - Render a bar below the modal header containing `<UrlInputView onExtract={handleExtract} initialUrl={lastUrl} />` and a dismiss (X) button
    - Dismiss button sets view back to 'tabs'
    - Tab content and footer still render below

    **extracting view**:
    - Tabs hidden, footer hidden
    - Modal body shows `<ExtractionView state={fetchState} onCancel={handleCancel} />`

    6. `handleExtract(url)` callback:
       - Store url in lastUrl state
       - Set view to 'extracting'
       - Call `startExtraction(url)`

    7. `handleCancel()` callback:
       - Call `cancel()` on the hook
       - If lastUrl exists, return to appropriate URL input view (url-cta if no brand data, url-inline if brand data exists) with lastUrl pre-filled
       - If no lastUrl, return to previous view

    8. Watch `fetchState.status`:
       - When 'done': For Phase 1, the result is stored but there's no review UI yet. Temporarily show tabs view (Phase 3 will add the review flow). Store result for downstream use.
       - When 'error': Stay on extracting view (ExtractionView handles error display with "Try Again" button which calls onCancel)
