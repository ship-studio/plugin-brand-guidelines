<feature>
  <name>Usage summaries in AI analysis</name>
  <files>src/analyzeTokens.ts, src/analyzeTokens.test.ts</files>
  <behavior>
    - AnalysisResult has a `usageSummaries` field: `{ colors: string; fonts: string; radii: string; spacing: string }`
    - buildPrompt output includes instruction #6 telling AI to generate 2-3 sentence prose usage summaries per category that reference token names and values
    - buildPrompt output JSON schema includes `"usageSummaries": { "colors": "string", "fonts": "string", "radii": "string", "spacing": "string" }`
    - parseAnalysisResponse returns usageSummaries when present in AI response
    - parseAnalysisResponse returns empty-string usageSummaries when AI response omits them (graceful degradation per user decision)
    - analyzeTokens returns AnalysisResult with usageSummaries field populated
  </behavior>
  <implementation>
    1. Add `UsageSummaries` interface to analyzeTokens.ts: `{ colors: string; fonts: string; radii: string; spacing: string }`.
    2. Add `usageSummaries: UsageSummaries` field to `AnalysisResult` interface.
    3. In `buildPrompt()`, add instruction #6 after the existing spacing instruction:
       "6. Generate a usage summary for each token category (colors, fonts, radii, spacing). Each summary should be 2-3 sentences of prose (not bullet points) explaining how to apply those tokens. Reference specific token names and values — for example, 'Use Primary #5C4EFA for CTAs and interactive elements.' Do NOT generate a summary for voiceNotes — the voice notes already serve as usage guidance."
    4. Extend the JSON schema string at the end of the prompt to include:
       `"usageSummaries": { "colors": "string", "fonts": "string", "radii": "string", "spacing": "string" }`
    5. In `parseAnalysisResponse()`, after parsing JSON, normalize missing usageSummaries:
       ```
       const empty = { colors: '', fonts: '', radii: '', spacing: '' };
       parsed.usageSummaries = { ...empty, ...(parsed.usageSummaries || {}) };
       ```
       This ensures graceful degradation — if AI omits summaries, all fields default to empty strings.
    6. Update test fixtures (`validResult`) to include usageSummaries.
    7. Add tests:
       - buildPrompt includes "usage summary" instruction text
       - buildPrompt JSON schema includes usageSummaries
       - parseAnalysisResponse preserves usageSummaries when present
       - parseAnalysisResponse defaults to empty strings when usageSummaries missing
       - parseAnalysisResponse defaults individual fields when partially present
  </implementation>
</feature>
